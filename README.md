# Контрагент

MVP сервиса проверки российских контрагентов. Пользователь вводит ИНН, ОГРН или название организации
и получает аналитическое досье с прозрачной оценкой риска (0–100), судами, исполнительными
производствами, банкротством, закупками и репутационным фоном.

> **Важно:** установочные данные (ЕГРЮЛ через DaData), лицензии/предупредительный список ЦБ (через
> `FinOrg.asmx`), а также выручка/расчётная прибыль, налоговая задолженность и дисквалификация
> директора — **реальные данные**, полученные официально и бесплатно (часть — live API, часть —
> через локальный ETL из открытых данных ФНС, см. ниже). Суды, ФССП, банкротство, закупки, полный
> баланс (активы/капитал), учредители, репутация — демонстрационные: у соответствующих источников
> либо нет открытых данных вообще, либо их сайты не отвечают на автоматические запросы (CAPTCHA/
> антибот-защита/нужно соглашение), либо (для «связей») сам датасет ФНС заброшен с 2021 года.
> Все находки исследования — в таблице ниже. Каждый раздел в интерфейсе явно помечен статусом
> источника (вкладка «Источники»), risk-engine исключает demo-данные из расчёта итогового балла
> (см. «Data quality» ниже) — демо-данные никогда не выдаются за настоящие.

## Исследование источников (что реально, что нет, и почему)

Проверено эмпирически: доступность официальных сайтов/API — с двух сетевых точек (облако и
локальная машина), доступность датасетов открытых данных — прямым скачиванием и разбором.

| Источник | Какие данные | Бесплатно | Способ доступа | Ограничения | Статус |
| --- | --- | --- | --- | --- | --- |
| **DaData** (прокси ЕГРЮЛ) | Название, статус, адрес, директор, ОКВЭД, дата регистрации, недостоверность | Да, 10 000 зап/день | REST API, ключ бесплатный | — | ✅ Подключено (live API) |
| **Банк России — FinOrg.asmx** | Лицензии участников финрынка | Да | Публичный SOAP, без ключа/CAPTCHA | Только для компаний-участников финрынка | ✅ Подключено (live API) |
| **Банк России — предупредительный список** | Признаки нелегальной деятельности | Да | Публичный JSON, без ключа | ~11 МБ, кеш 6 часов | ✅ Подключено (live API) |
| **ФНС open data — доходы/расходы** (`revexp`) | Выручка, расходы (⇒ расчётная прибыль) | Да | Официальный XML-дамп, ~100 МБ/год | ТОЛЬКО доходы/расходы — активов/капитала в открытых данных нет нигде; один снимок в год; покрывает ~1,9 млн юрлиц из ~4-5 млн (не все) | ✅ Подключено (ETL → SQLite) |
| **ФНС open data — налоговая задолженность** (`debtam`) | Недоимка/пени/штрафы | Да | Официальный XML-дамп, ~83 МБ | Снимок на дату выгрузки | ✅ Подключено (ETL → SQLite) |
| **ФНС open data — дисквалифицированные лица** | ФИО + компания, из которой дисквалифицирован | Да | Официальный CSV, ~3,4 МБ, актуальный | Сверяется строго по (ФИО + название ИМЕННО этой компании) — без обхода false positive на однофамильцев | ✅ Подключено (ETL → SQLite) |
| **ФНС open data — спецрежимы** (`snr`) | УСН/АУСН/ЕСХН/СРП | Да | Официальный XML-дамп, ~63 МБ | Информационный признак, не влияет на risk-engine | ✅ Подключено (ETL → SQLite) |
| **ФНС open data — уплаченные налоги** (`paytax`) | Сумма уплаченных налогов/год | Да | Официальный XML-дамп, ~218 МБ | Скачан, ETL не реализован в этой итерации | ⏳ Скачан, не подключён |
| **ФНС open data — массовый руководитель/учредитель** | Связи «директор → другие юрлица» | Формально да | CSV | Датасет ФАКТИЧЕСКИ ЗАБРОШЕН — последнее обновление 22.05.2021, файлы почти пустые | ❌ Не подключено (мёртвый датасет) |
| **ФНС — полный баланс (форма 1+2)** | Активы, капитал, кредиторская задолженность | Формально да (ГИР БО) | bo.nalog.ru — интерактивный сервис | Не отвечает на автоматические запросы (сетевая антибот-защита); открытых bulk-данных с балансом не существует | ❌ Нет легального бесплатного способа |
| **КАД Арбитр** (kad.arbitr.ru) | Дела, стороны, суммы | Официально да (для человека) | — | Поиск защищён CAPTCHA | ❌ Нет (CAPTCHA не обходится) |
| **ФССП** (fssp.gov.ru) | Исполнительные производства | Есть API, но по соглашению | — | Нужна аккредитация; сайт не отвечает на автозапросы | ❌ Нет |
| **Федресурс** (fedresurs.ru) | Банкротство, значимые сообщения | Не подтверждено | — | 401 Unauthorized на запросы без сессии | ❌ Нет |
| **ЕИС закупки** (zakupki.gov.ru) | Контракты, РНП | Официально да | Открытые данные (FTP/XML) | Портал и FTP не отвечали на запросы при проверке | ❌ Нет |
| **Веб-репутация** | Упоминания в СМИ | Зависит от провайдера | — | Платный поисковый API сознательно не подключён (решение задачи) | ⚠️ Демо (abstraction готова) |

Источники со статусом «Нет» помечены в приложении `blocked` — «подключить бесплатно и легально сейчас
нельзя» (с точной причиной на вкладке «Источники»), в отличие от `demo` — «не подключено по решению
продукта» (веб-репутация).

## ETL / импорт открытых данных ФНС

Финансовые и налоговые данные не запрашиваются у ФНС в момент проверки пользователя — заранее
импортируются в локальную SQLite (`data/kontragent.db`, в `.gitignore`, не коммитится) командами:

```bash
npm run import:finance    # выручка/расходы — скачайте data/raw/revexp.zip вручную (см. таблицу выше), ~100 МБ
npm run import:fns-risk   # налоговая задолженность + дисквалификация — data/raw/debtam.zip + registerdisqualified.csv
```

Каждый скрипт при первом запуске выведет точный URL, если нужного файла нет в `data/raw/` — файлы
скачиваются вручную (не автоматически из кода) и кладутся в `data/raw/<имя>.zip`. Архитектура
(`scripts/lib/db.mjs` — ETL, `src/lib/db/sqlite.ts` — чтение из приложения) использует встроенный
`node:sqlite` (Node 22.5+) — без дополнительных зависимостей. Обновлять данные — раз в год (датасеты
ФНС публикуются ежегодно); без обновления `providers/girbo.ts` сам пометит устаревший снимок статусом
`stale`.

**Перенос на PostgreSQL/Supabase:** меняется только `src/lib/db/sqlite.ts` (и `scripts/lib/db.mjs` для
ETL) — остальной код обращается к типизированным функциям `providers/financeDb.ts` и
`providers/fnsRiskDb.ts`, не к SQL напрямую.

**Ограничение для деплоя на Vercel:** serverless-функции Vercel не хранят файлы между запросами
надёжно — `data/kontragent.db` нужно либо собирать как часть деплоя (файл лежит в билде, доступен на
чтение), либо мигрировать на Postgres/Supabase. Это не блокирует MVP: при отсутствии БД `girbo.ts`
и `fnsRiskDb.ts` автоматически и тихо откатываются на демо-данные — сервис не падает.

## Data quality: демо-данные никогда не участвуют в Risk Score

Каждый факт в досье несёт `meta.reliability`: `"verified"` (реальный источник), `"demo"` (демо-
генератор) или `"unconfirmed"` (реальный источник не ответил вовремя). **Каждое правило risk-engine**
(`src/lib/risk-engine/rules.ts`) проверяет reliability своего источника и возвращает `[]` (нулевой
вклад в балл), если данные не `"verified"` — это не агрегированная фильтрация постфактум, а гейт на
уровне каждого правила, так что для одной и той же категории («корпоративный») могут одновременно
учитываться реальные факты (ФНС/ЦБ) и игнорироваться демо-факты (учредители) — раздельно.

Рядом с рейтингом показывается **«Достоверность оценки: XX%»** — доля из 8 категорий риска
(финансовый/судебный/исполнительный/банкротный/корпоративный/налоговый/закупочный/репутационный),
подкреплённых реальными данными хотя бы по одному источнику (`RiskAssessment.coverage`,
`src/lib/risk-engine/index.ts`). При покрытии ниже 50% показывается предупреждение «Оценка
предварительная: часть источников недоступна».

## Стек

Next.js (App Router) · TypeScript · Tailwind CSS · минимум зависимостей (jsPDF — единственная
дополнительная библиотека, нужна для генерации PDF).

## 1. Локальный запуск

```bash
npm install
npm run dev
```

Откройте [http://localhost:3000](http://localhost:3000) — сервис полностью работает без каких-либо
переменных окружения (используются демо-данные и шаблонное AI-заключение без обращения к ИИ).

Полезные команды:

```bash
npm run lint     # ESLint
npx tsc --noEmit # проверка типов
npm run build    # production-сборка
npm start        # запуск собранного приложения
```

## 2. Переменные окружения (опционально)

Скопируйте `.env.example` в `.env.local` и при желании укажите ключ Google Gemini:

```bash
cp .env.example .env.local
```

| Переменная       | Обязательна | Назначение                                                                 |
| ---------------- | ----------- | --------------------------------------------------------------------------- |
| `GEMINI_API_KEY` | Нет         | Ключ Google Gemini для AI-резюме досье. Без ключа используется шаблонное заключение (без ИИ) — сервис остаётся полностью рабочим. |
| `GEMINI_MODEL`   | Нет         | Название модели Gemini (по умолчанию экономичная `gemini-3.5-flash-lite`). |
| `DADATA_API_KEY` | Нет         | Ключ DaData для реальных данных ЕГРЮЛ (установочные данные компании). Без ключа — демонстрационные установочные данные, как и для остальных разделов. |

Ключ Gemini — [aistudio.google.com/app/apikey](https://aistudio.google.com/app/apikey).
Ключ DaData — регистрация на [dadata.ru](https://dadata.ru/api/find-party/), бесплатный тариф до
10 000 запросов/день, ключ виден сразу в личном кабинете после подтверждения email.
Никогда не коммитьте `.env.local` в репозиторий — он уже в `.gitignore`.

## 3. Создание репозитория на GitHub

1. Зайдите на [github.com/new](https://github.com/new).
2. Название репозитория: `kontragent-mvp`. Не добавляйте README/`.gitignore`/лицензию — они уже есть в проекте.
3. Нажмите «Create repository».

## 4. Публикация проекта в GitHub

В корне проекта (`kontragent-mvp`):

```bash
git init
git add .
git commit -m "Initial commit: Контрагент MVP"
git branch -M main
git remote add origin https://github.com/<ваш-логин>/kontragent-mvp.git
git push -u origin main
```

## 5. Подключение GitHub к Vercel

1. Зайдите на [vercel.com/new](https://vercel.com/new) и авторизуйтесь через GitHub.
2. Выберите репозиторий `kontragent-mvp` → «Import».
3. Vercel сам определит Next.js — framework preset менять не нужно.

## 6. Environment Variables в Vercel

На экране настройки импорта (или позже в Project → Settings → Environment Variables) добавьте:

- `GEMINI_API_KEY` — при наличии ключа (опционально)
- `GEMINI_MODEL` — например, `gemini-3.5-flash-lite` (опционально)
- `DADATA_API_KEY` — при наличии ключа, для реальных данных ЕГРЮЛ (опционально)

Без этих переменных сервис задеплоится и будет работать — просто AI-резюме будет шаблонным, а
установочные данные компании — демонстрационными.

## 7. Deploy

Нажмите «Deploy». Через 1–2 минуты Vercel выдаст рабочую ссылку вида
`https://kontragent-mvp.vercel.app`. При каждом новом push в `main` Vercel будет собирать и
выкатывать новую версию автоматически.

## Архитектура (кратко)

- `src/types/dossier.ts` — единый тип `CompanyDossier` и все связанные сущности.
- `src/lib/providers/*` — независимые адаптеры источников (ФНС, ГИР БО, КАД Арбитр, ФССП, ЕИС
  закупки, Федресурс, ЦБ РФ, веб-репутация). Каждый адаптер можно заменить на реальную интеграцию
  независимо от остальных — бизнес-логика ни к одному провайдеру не привязана напрямую.
  `fns.ts` — гибридный: при наличии `DADATA_API_KEY` берёт установочные данные из реального ЕГРЮЛ
  (`dadata.ts` — клиент DaData), иначе (и для учредителей/связанных организаций всегда) — из
  демо-генератора `mock-data/generator.ts`. `cbr.ts` — тоже гибридный: реальные лицензии и
  предупредительный список через официальный бесплатный SOAP/JSON Банка России (`cbrFinOrg.ts`),
  ключ не требуется. `cache.ts` — общий in-memory TTL-кеш для обоих реальных источников (по ТЗ —
  не дёргать внешние API без необходимости на повторных проверках).
- `src/lib/risk-engine/*` — расчёт риска 0–100 обычным TypeScript-кодом (без ИИ), с полной
  трассировкой «почему получился такой балл» и отдельным модулем оценки риска сделки.
- `src/lib/ai/*` — абстракция `AIProvider`: `GeminiAIProvider` + `TemplateAIProvider` (fallback без
  ключа/при сбое). ИИ получает только уже посчитанные факты и рейтинг и не может их придумывать или
  менять.
- `src/lib/pdf/generateDossierPdf.ts` — серверная генерация PDF-досье (jsPDF + встроенный шрифт PT
  Sans с поддержкой кириллицы).
- `src/lib/repository/*` — абстракция хранилища; сегодня in-memory, позже подключается
  PostgreSQL/Supabase без изменений в остальном коде.
- `POST /api/check`, `POST /api/deal-risk`, `POST /api/pdf` — публичные API-эндпоинты.

Недоступность одного источника данных не ломает всю проверку — соответствующий раздел досье
помечается статусом источника (см. вкладку «Источники» на странице компании).
